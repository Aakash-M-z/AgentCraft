# Enterprise AI Report Generator

**Status:** Draft  
**Created:** 2026-06-29  
**Feature Type:** Flagship Enhancement  
**Priority:** High

## Executive Summary

Transform AgentCraft's Output Node from displaying raw JSON into an **Enterprise AI Report Generator** that automatically produces professional, executive-ready reports with interactive dashboards, PDF generation, charts, and multiple export formats. This positions AgentCraft as an enterprise-grade automation platform comparable to Salesforce, SAP, ServiceNow, Microsoft Power Platform, and UiPath.

## Requirements

**Priority:** Must Have

**Acceptance Criteria:**

### Data Model

**Report Data Structure:**
```typescript
interface ReportData {
  id: string;
  executionId: number;
  workflowId: number;
  workflowName: string;
  workflowType: string;
  timestamp: string;
  
  // Executive Summary
  executiveSummary: {
    businessPurpose: string;
    keyFindings: string[];
    riskAssessment: string;
    recommendation: string;
    finalDecision: string;
  };
  
  // Key Metrics
  metrics: {
    key: string;
    value: string | number;
    badge?: 'success' | 'warning' | 'error' | 'info';
    icon?: string;
  }[];
  
  // Detailed Sections
  sections: {
    title: string;
    type: 'table' | 'list' | 'keyvalue' | 'text';
    data: any;
  }[];
  
  // Charts
  charts?: {
    type: 'pie' | 'bar' | 'line' | 'gauge';
    title: string;
    data: any;
  }[];
  
  // Audit Trail
  audit: {
    executionId: number;
    workflowId: number;
    timestamp: string;
    triggeredBy: string;
    duration: string;
    nodeCount: number;
    aiModel: string;
    validationStatus: string;
    digitalFingerprint: string;
    auditLog: string[];
  };
  
  // Raw data for developer mode
  rawData?: any;
}
```

### Database Schema Extension

**reports table:**
```sql
CREATE TABLE reports (
    id SERIAL PRIMARY KEY,
    execution_id INTEGER REFERENCES executions(id) ON DELETE CASCADE,
    report_type VARCHAR(100) NOT NULL,
    report_data JSONB NOT NULL,
    pdf_url TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_reports_execution ON reports(execution_id);
```

## Technical Decisions

### TD-1: PDF Library Choice
**Decision:** Use `reportlab` for Python-based PDF generation  
**Rationale:**
- Mature, well-maintained library
- Fine-grained control over PDF layout
- Supports enterprise features (headers, footers, watermarks)
- Better server-side performance than browser-based solutions

**Alternatives Considered:**
- WeasyPrint (CSS-based, less control)
- wkhtmltopdf (deprecated, security concerns)
- Browser-based PDF.js (client-side, slower)

---

### TD-2: Chart Library
**Decision:** Use Recharts for React chart rendering  
**Rationale:**
- React-native, integrates seamlessly
- Professional appearance
- Good documentation and community support
- Supports all required chart types

**Alternatives Considered:**
- Chart.js (not React-native)
- D3.js (too complex, steep learning curve)
- Victory (less popular, fewer examples)

---

### TD-3: AI Executive Summary
**Decision:** Use existing Groq AI integration with specialized prompt  
**Rationale:**

### TD-4: Template System Architecture
**Decision:** Use factory pattern with template registry  
**Rationale:**
- Flexible and extensible
- Easy to add new templates without modifying core code
- Clear separation of concerns
- Supports template inheritance

**Pattern:**
```python
class TemplateRegistry:
    _templates: Dict[str, ReportTemplate] = {}
    
    @classmethod
    def register(cls, workflow_type: str, template: ReportTemplate):
        cls._templates[workflow_type] = template
    
    @classmethod
    def get_template(cls, workflow_type: str) -> ReportTemplate:
        return cls._templates.get(workflow_type, cls._templates["generic"])
```

---

### TD-5: Report Caching Strategy
**Decision:** Cache report data in database, generate PDF on-demand  
**Rationale:**
- Report data rarely changes after execution completes
- PDF generation is slow, should be async
- Multiple users can share same PDF
- Reduces server load

**Implementation:**
- Store report JSON in `reports` table
- Generate PDF asynchronously on first request
- Store PDF URL in database
- Serve cached PDF for subsequent requests
- Invalidate cache if execution is re-run
